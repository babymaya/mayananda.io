Shader Studio

A GLSL environment where a person and Claude work on the same running shader. One renderer drives a live window and a headless capture, so the image that Claude reads is the image that you see.

Status

I built the renderer, the capture tool, the code panel, the chat panel, and the chat bridge. Each part was tested on its own. A full live turn, where a chat message makes Claude edit the running shader, has not been run. The lock that handles edit conflicts is not built.

  • Same pixels. At the same resolution, a capture matches the live window. This removes the need to describe an image in words.
  • Shader format. A shader is one Shadertoy-style main function. A comment line in the shader connects an input image.
  • Feedback. A shader can read its previous frame from a float buffer. A Game of Life demo tests this.
  • Capture. A capture can take frames at chosen times, or step a simulation and write a contact sheet.

Studio mode

 Code panel (left)      Chat panel (right)
       |                       |
       | save                  | message file
       v                       v
 Shader file  <-- edit --  Chat bridge > Claude CLI
       |                       |
       v                       | reply file
 Live shader background  <-----+
  • Overlay. Translucent panels sit over the fullscreen shader. Outlined text stays readable over a bright image, and one key dims the background.
  • Code panel. The panel mirrors the shader file and highlights changed lines. Edit mode saves through the same hot-reload path.
  • Chat bridge. Two append-only files carry the messages, and each file has one writer. The local Claude CLI is the only model caller, so the application makes no API calls.
  • Two programs. The interface library includes its own GLFW, which cannot link with the GLFW of the live window. The studio is therefore a separate program, and both programs share the renderer.
